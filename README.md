# MVP2 — API базы знаний

FastAPI-бэкенд: загрузка и индексация документов (chunking + эмбеддинги
OpenAI + pgvector), поиск по базе знаний и чат с ассистентом (RAG),
включая потоковый (SSE) ответ.

## Компоненты

- **api** — FastAPI-приложение (Uvicorn), `main:app`.
- **worker** — Celery-воркер (`app/workers/celery.py`), очередь `indexing`:
  парсинг документов, chunking, эмбеддинги. Синхронный (использует
  отдельный sync-движок SQLAlchemy, `app/db/sync_session.py`).
- **db** — PostgreSQL с расширением `pgvector` (векторный поиск по чанкам).
- **redis** — брокер сообщений для Celery (результаты задач не хранятся —
  статус индексации живёт в таблице `documents`, не в Celery backend).

## Внешние зависимости (не поднимаются в docker-compose)

- **OpenAI API** — эмбеддинги и генерация ответов (`OPENAI_API_KEY`).
  Без него индексация документов и чат не работают.
- **SMTP** — отправка кода сброса пароля (опционально, если фича не
  используется — можно оставить пустым).

## Быстрый старт (docker-compose)

```bash
cp .env.example .env
# заполнить SECRET_KEY, OPENAI_API_KEY (обязательны),
# остальное можно оставить по умолчанию для локального запуска

docker compose up --build
```

`api` сам применяет миграции (`alembic upgrade head`) перед стартом.
При первом запуске также автоматически создаётся служебный пользователь
(см. `main.py: _ensure_default_user`) — пока в проекте нет
самостоятельной регистрации, все диалоги ведутся от одного встроенного
аккаунта или от аккаунтов, заводимых админом (`/api/v1/admin/users`).

Открыть `http://localhost:8000/docs` — Swagger UI.

## Хранилище файлов

`STORAGE_BACKEND=local` — файлы лежат на диске (`uploads/`, volume
`uploads` в docker-compose). **Это persistent volume, не эфемерное
хранилище контейнера** — при переезде/масштабировании на несколько
инстансов api/worker нужно либо общее сетевое хранилище (NFS/S3-подобное),
либо явно спланировать миграцию `storage_backend` на объектное хранилище.

## Прод-окружение (managed Postgres)

`app/db/ssl.py` / `app/db/sync_ssl.py` заточены под managed Postgres
(например Timeweb Cloud) с TLS: `DB_SSL=verify-full` +
`DB_SSL_ROOT_CERT=<путь к root CA внутри контейнера>`. Для локального
docker-compose оставить `DB_SSL` пустым (SSL выключен, обычное
подключение к контейнеру `db`).

## Миграции вручную (без docker-compose)

```bash
alembic upgrade head
```

## Известные ограничения / на заметку

- `CHAT_MODEL` (используется в `app/services/llm.py`) — убедиться, что
  в `.env` именно это имя переменной, а не что-то другое: любая
  нераспознанная переменная тихо игнорируется (`extra="ignore"` в
  `Settings`), и код молча откатится на дефолт `gpt-4o-mini`.
- Стриминг чата (`POST /api/v1/dialog/chat/stream`) отдаёт
  `text/event-stream` — если перед api будет nginx/другой обратный
  прокси, обязательно отключить буферизацию для этого пути (иначе
  токены будут приходить не по мере генерации, а одним куском в конце).
